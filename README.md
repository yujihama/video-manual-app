# 動画から手順書

PC操作の録画を取り込み、画像付きの観測下書きを作るローカルアプリです。各手順の「動画で確認」と根拠画像から、動画の該当位置を再生できます。

## 使い方

1. `起動.cmd`をダブルクリックします。ブラウザで `http://127.0.0.1:8765` が開きます。
2. 「サンプルで試す」で、架空の備品操作動画と保存済みの生成結果を確認できます。サンプルではAPIを呼びません。
3. 「新しい動画」から自分のMP4/WebMなどを選び、「動画を読み込む」を押します。この段階はローカル処理です。
4. 「生成の準備」で、画面画像をOpenAIに送って入力数と最大費用を確認します。金額を確認し「生成する」を押すと手順書を作ります。
5. 手順の時刻・画像を押して動画と照合します。「内容を編集」で題名・説明・操作対象・値・要確認事項を修正し、保存できます。
6. 「HTML＋動画ZIP」または「Word」で保存します。

編集画面では左側に動画と手順一覧、右側に文書を表示します。参照画像と操作の確認事項は各手順で展開できます。出力操作は画面上部にあります。

## 動画とのリンク

- アプリ画面：各手順と各根拠画像から動画の参照時刻へ移動。動画の現在位置に対応する手順も強調します。
- HTML＋動画ZIP：**全て展開して`manual.html`を開く**と、アプリを停止しても、同梱の`video.mp4`を各手順の位置から再生できます。`images`も一緒に保管してください。
- Word：各手順の動画リンクが、このPCで動くアプリを該当時刻で開きます。アプリを停止するとリンクは利用できません。他のPCに渡す場合はHTML＋動画ZIPをご利用ください。
- 参照範囲は元画像の時刻から計算しています。クリックの瞬間を断定するものではありません。文章の編集でも根拠と時刻を保持し、並べ替えは行いません。

## 別のWindows PCでの準備

Python3.11以上を用意し、PowerShellで`setup.ps1`を実行します。専用venvに依存を入れ、グローバル環境は変更しません。実行ポリシーによりps1が利用できない場合は、同じフォルダで`python -m venv .venv`と`.venv\Scripts\python.exe -m pip install -r requirements.txt`を実行します。

FFmpegとffprobeを用意し、同じフォルダの場所を`VIDEO_MANUAL_FFMPEG_DIR`に設定します。APIキーは`OPENAI_API_KEY`としてプロセス環境変数へ安全に設定してください。アプリから新規キーの発行やキーの永続保存は行いません。FFmpeg実行ファイル・venv・ユーザー動画・キー値は配布物に含めません。

モデルは検証に使った`gpt-6.1-terra`です。画像と抽出指示だけを送信し、`store=false`、自動再試行なしで呼び出します。予算は`data/budget.json`で未確定分も含めて記録します。初期のアプリ累計上限はUSD0.60です。明示的に変更する場合は起動前の`VIDEO_MANUAL_BUDGET_USD`で指定します。料金表の変更や請求書との突合は別途確認してください。

## 現版の範囲

- 動画の容量・再生時間・抽出画像総数に固定の上限はありません。保存先の空き容量が必要です。動画変換に5分の打ち切り時間は設けていません。
- 長い動画は順次デコードして画像をディスクへ保存します。LLMには40枚単位と直前2枚の文脈を送り、入力枠を超える場合はさらに区間を分割します。全体を一度にモデルへ送信しません。短い動画の画像抽出には従来のwatch-skillを使用します。
- 抽出間隔は0.5・1・2・5・10・30秒です。間隔を広げると費用や処理量は減りますが、一瞬のメニューや細かい操作を見落とす場合があります。長い動画でも細かい操作を確認する場合は0.5〜2秒を選んでください。
- 区間ごとの見積もりを合計し、生成前に残りの最大費用を表示します。累計費用の予算管理は維持しています。長い動画で予算不足になる場合は、起動前に`VIDEO_MANUAL_BUDGET_USD`を明示的に設定してください。ファイル上限の撤廃によって予算が自動で増えることはありません。
- 完了済み区間の応答・使用量を保存します。エラー後の「続きの生成を準備」で未完了区間だけを再見積もりします。結果が不明な課金要求は再送せず、利用状況の確認まで停止します。区間境界の重複や根拠順序の異常は出力を保留します。
- MP4/H.264とWebMで確認済み。他のコンテナもFFmpegが読めれば入力できます。再生用にはH.264 MP4を作り、元の動画を保持します。
- 音声は再生用動画に保持します。現版の手順抽出は画面だけを使用し、音声文字起こしは未対応です。
- 録画に見えない操作や保存完了を補完しない契約で抽出します。根拠参照・順序の異常時は文書出力を保留します。意味の正しさの保証や自動承認は行いません。
- サンプルは架空のWeb画面を実際に操作して録画したものです。各生成結果は作業責任者の承認前の下書きとして扱います。
- 待受は127.0.0.1のみ。同じPCで使う設計です。インターネットへの公開・複数利用者向け認証は含みません。

## テスト

セットアップ後、`.venv\Scripts\python.exe -m unittest test_app test_long_video -v`でオフライン検証を実行できます。保存済みの架空サンプルを使い、OpenAI APIは呼びません。根拠画像の変更検知、時系列異常時の保留、編集時の根拠保持、HTML・Wordの動画リンク、費用予約に加え、複数区間の結合・再開・入力枠に応じた分割を確認します。

起動中のアプリに対するHTTP検証は`.venv\Scripts\python.exe verify_http.py`で実行できます。`verify_browser.py`は開発用の任意テストで、別途PlaywrightとChromeが必要です。

長い動画の実処理は`.venv\Scripts\python.exe verify_long_video.py`で確認できます。610秒の合成MP4に約301MiBのパディングを付け、HTTPアップロード・FFmpeg処理・終盤の参照・ZIP出力まで実行します。`.venv\Scripts\python.exe verify_long_video.py --duration 3601 --interval 10 --padding-mib 0`では1時間1秒を検証します。モデル応答だけを模擬し、有料APIは呼びません。動画・画像・結果は`tests-output/`へ保存します。

`demo/`は架空のWeb画面を録画したサンプル動画・画像・保存済みの生成結果です。実際の利用者の録画、生成履歴、APIキー、実行環境はリポジトリに含めません。
